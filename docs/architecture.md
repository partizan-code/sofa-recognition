# Архитектура и хранение

[К обзору проекта](../README.md)

## Режимы распознавания

| Режим | Выбор модели мебели | Цвет / конфигурация |
|---|---|---|
| Vision Only | LLM сравнивает фото с карточками всех доступных моделей каталога | Анализ исходного фото |
| Cohere Embeddings | TOP-1 уникальная модель по cosine с порогом отказа | `null` |
| Voyage Embeddings | То же, с индексом Voyage | `null` |
| Cohere + Vision | Cohere TOP-5 уникальных моделей → визуальное сравнение LLM | Анализ исходного фото |
| Voyage + Vision | Voyage TOP-5 уникальных моделей → визуальное сравнение LLM | Анализ исходного фото |

Vision Only использует подписанные эталоны: название товарной модели определяется
сопоставлением с каталогом. Его TOP-5 — ранжирование LLM, без cosine.
В гибридных режимах таблица показывает исходных кандидатов поиска; финальная модель
может отличаться от TOP-1.

Каждая карточка содержит до трёх эталонных ракурсов. В гибридном режиме лучший
найденный эталон показывается первым. Число ракурсов ограничивает размер контекста
и настраивается через `REFERENCE_VIEWS` в [config.py](../config.py).

Порог cosine применяется только в режимах Embeddings. Отказ Vision задаётся
промптом и возможностью вернуть `null`. Цвет и конфигурация эталона не копируются
в результат: Vision определяет их по исходному фото.

## Внешние API и валидация

Embeddings и Vision вызываются через OpenRouter. Идентификаторы моделей, адреса
API и параметры находятся в [config.py](../config.py); ID моделей можно менять
в интерфейсе. Первый элемент `VISION_MODELS` задаёт начальный выбор и
`Settings.vision_model`. После изменения конфигурации перезапустите приложение.
Сохранённые эксперименты с прежними моделями остаются в журнале.

Embeddings-запрос содержит изображение в виде `image_url` с data URL.
Для эталонов используется `search_document`, для исходного фото — `search_query`.
Vision использует `/chat/completions`, изображения в `messages` и strict JSON Schema.
Маршрутизация требует поддержки переданных параметров.

Ответ дополнительно проверяется Pydantic. Неизвестная модель, дубли кандидатов,
некорректный JSON, обрезанный ответ и HTTP-ошибка не сохраняются в кэш как успешный
результат. Автоматических повторов платных запросов нет; таймаут — 60 секунд.

Наличие ID в конфигурации не гарантирует доступность модели конкретному API-ключу.
Реальные ответы, поддержку параметров и расходы следует проверять в эксперименте.

## Индексы, кэш и результаты

| Путь | Содержимое |
|---|---|
| `data/catalog/` | JSON-каталог и эталонные фотографии |
| `data/test/` | Независимые тестовые фотографии и необязательная разметка |
| `data/indexes/<provider>/<model-hash>.npz` | Отдельные индексы провайдеров и моделей |
| `data/cache/` | Успешные проверенные ответы API |
| `data/results/` | Запуски с настройками, разметкой и метриками |
| `data/uploads/` | Загруженные изображения |
| `logs/errors.log` | Диагностические сообщения |

NPZ загружается без pickle. Подпись индекса учитывает модель, каталог, хэши фотографий
и preprocessing; изменение этих данных требует пересборки. Частично построенный
индекс не заменяет готовый. Уже рассчитанные API-ответы остаются в кэше, что позволяет
продолжить обработку при повторной сборке.

Ключ кэша зависит от полного запроса, модели, промпта, изображений и API URL.
API-ключ в кэш не записывается. TTL нет: ответ переиспользуется до изменения запроса
либо явного обхода кэша. JSON-записи выполняются атомарно.

Весь `data/`, `logs/`, `.cache/`, `.env` и `.venv` исключены из Git.
Форматы каталога и тестового набора приведены в [руководстве пользователя](usage.md).
