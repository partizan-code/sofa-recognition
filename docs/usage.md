# Запуск, данные и работа с приложением

[К обзору проекта](../README.md)

## Окружение

Проект использует Python 3.13, mise и uv. mise выбирает интерпретатор,
uv создаёт и синхронизирует проектную `.venv` по `uv.lock`.
Перед настройкой установите эти инструменты и интерпретатор нужной версии.

```sh
mise run setup
```

Создайте `.env` по образцу `.env.example` и задайте `OPENROUTER_API_KEY`.
Приложение автоматически читает `.env` из корня; переменные процесса имеют приоритет.
Файлы окружения с реальными ключами не должны попадать в Git.

После подготовки каталога запустите:

```sh
mise run start
```

Адрес приложения: <http://127.0.0.1:8501>. Повторный запуск не синхронизирует
зависимости; после их изменения выполните setup.

Если зависимости уже установлены в `.venv`, приложение можно запустить без mise.

Windows, PowerShell:

```powershell
.\.venv\Scripts\python.exe -B -m streamlit run main.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

macOS:

```sh
.venv/bin/python -B -m streamlit run main.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

## Каталог эталонов

Каталог и изображения не распространяются вместе с кодом. Подготовьте собственные
эталонные фотографии JPEG, PNG или WebP и файл `data/catalog/catalog.json`.
Минимальная структура:

```text
data/
  catalog/
    catalog.json
    reference-01.webp
```

Пример содержимого `catalog.json`:

```json
[
  {
    "name_file": "reference-01.webp",
    "model": "Elias",
    "color": "Серый",
    "type": "Угловой"
  }
]
```

Замените значения своими данными. Файл изображения должен существовать рядом
с JSON. `name_file` — уникальное имя файла без пути; для эталона `model` обязателен.
Одна модель может иметь несколько фотографий с разными именами файлов.
Для содержательного сравнения добавьте несколько моделей и ракурсов.

В файлах данных поле `type` задаёт конфигурацию: `Прямой`, `Угловой` или `П-образный`.
В результате распознавания это поле называется `configuration`.

## Тестовый набор

Добавьте независимые фотографии в `data/test/`. Необязательный `test.json`
рядом с ними задаёт известные параметры для оценки:

```json
[
  {
    "name_file": "room-01.jpg",
    "model": "Elias",
    "color": "Серый",
    "type": "Угловой"
  },
  {
    "name_file": "unlabeled.jpg",
    "model": null,
    "color": null,
    "type": null
  }
]
```

При отсутствии `test.json` приложение перечисляет фотографии папки без разметки.
При наличии файла набор определяется его записями. Неизвестные поля можно опустить.
Пути в `name_file` запрещены; перечисленные изображения должны существовать рядом.
Исходная разметка теста не отправляется LLM.

`null` в разметке означает отсутствие известного ответа и не участвует в оценке.
Это не метка «заведомо неизвестная модель»; для оценки таких случаев нужно отдельно
анализировать результаты.

## Первый эксперимент

1. Подготовьте каталог и независимый тестовый набор.
2. Для режимов с embeddings постройте индексы Cohere и Voyage отдельно.
   Построение вызывает платные API; повторный запуск использует сохранённый кэш.
   Статусы «готов», «отсутствует», «требует пересборки» восстанавливаются с диска
   и проверяются без API-запросов.
3. Выберите режим, модели и промпт слева, затем примените настройки.
4. Переключайте фотографии стрелками или списком. Автораспознавание включено
   по умолчанию и может выполнять платные запросы при переключении.
5. В разделе «Пакетное сравнение методов» запустите выбранные режимы на одном наборе.
   Для замеров времени и стоимости API включите обход кэша.
6. Выберите эксперименты в сводке. По умолчанию учитываются только общие фотографии.
   Журнал и отдельные результаты можно скачать в JSON.

Можно загрузить отдельное фото без разметки или выбрать «Каталог: самопроверка».
Самопроверка исключает эталоны с тем же SHA-256 содержимого, даже если имя файла
другое. Она не заменяет оценку на независимых снимках.

## Палитра цветов

Vision выбирает цвет из 33 названий `COLOR_PALETTE` в [config.py](../config.py).
Полный список доступен в боковой панели «Палитра цветов». Сохраняется точное
написание, например `Желтый`, `Зеленый`, `Чёрный`.

Палитра хранится локально; приложение не загружает её из Google Drive при запуске.
Она передаётся в промпте и ограничивает JSON Schema и проверку Pydantic.
Редактирование промпта не расширяет допустимый список. Цвет вне палитры считается
ошибкой и не кэшируется как успешный ответ. Оттенок определяется по исходному фото,
независимо от цвета эталона; без Vision цвет остаётся `null`.

Для обновления измените `COLOR_PALETTE` и перезапустите приложение. Это меняет ключи
Vision-кэша и экспериментов; индексы пересобирать не нужно. Старые результаты сохраняют
исходные названия цветов. Для новой разметки используйте точные названия из палитры.

## Диагностика

При ошибке пакетного сравнения интерфейс показывает фото, режим, тип исключения
и причину. Сообщения сохраняются в `logs/errors.log`: ротация по 1 MB, до трёх архивов.
Для Vision указываются `finish_reason` либо несовпавшие модели/кандидаты;
ошибки валидации показывают поля и тип нарушения без исходных значений.
API-ключи и изображения в журнал не выводятся.

Локальные изображения, каталог, индексы, результаты, логи, кэш и окружение исключены
из Git. При переносе проекта на другую машину данные нужно переносить отдельно.

Метрики и ограничения сравнения описаны в [методике экспериментов](evaluation.md).
